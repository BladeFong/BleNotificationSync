# 桌面端代码审查报告

## 总体评价

代码整体质量良好，架构清晰，模块职责分明。但存在一些安全、健壮性和可维护性问题需要关注。

## 关键发现

### 🔴 严重问题

1. **命令注入风险** (`config.rs:103-147`)
   - ⚠️ **部分修复**：`$args[0]` 参数化在 Rust + PowerShell 组合中不起作用（`-args` 被解释为脚本一部分）
   - 当前方案：保留字符串拼接，添加安全注释（输入字符受限：device_id=十六进制，package=包名字符）
   - 结论：当前场景安全，但 `$args` 方案不可行

2. **XSS 风险** (`main.js:22`)
   - ✅ **已修复**：`innerHTML` 改为 `textContent` + `createTextNode`
   - 修复内容：手动构建 DOM 节点，避免 HTML 注入

3. **Mutex 死锁风险** (`storage.rs:48-64`)
   - ✅ **验证为误报**：所有场景锁顺序一致（devices → silent），无需修改

### 🟡 重要问题

1. **unsafe impl Send/Sync** (`lib.rs:73-74`)
   - ✅ **已处理**：添加 `# Safety` 文档说明安全性理由
   - 分析：所有字段通过 Mutex 保护，CheckMenuItem 只在主线程创建，其他线程只通过锁访问

2. **PowerShell 注入** (`notify.rs:54-96`)
   - ✅ **已修复**：改用 `$args[0]`/`$args[1]` 参数化传递 title/body
   - 修复内容：移除字符串转义，使用 `-args` 参数传递

3. **错误处理不一致**
   - ⏳ 待处理：部分地方使用 `unwrap()`，部分使用 `map_err`

### 🟢 建议改进

1. **协议验证** (`protocol.rs`)
   - ✅ **已修复**：添加 `total_seq == 0` 和 `seq >= total_seq` 校验

2. **前端 i18n** (`main.js`)
   - ⏳ 待处理：多处硬编码中文字符串

3. **资源管理** (`ble.rs`)
   - ⏳ 待处理：Windows BLE 资源清理可能不完整
